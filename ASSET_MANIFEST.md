# Lanternmere — asset & license manifest

Per the brief: "All third-party and generated assets need a license/provenance manifest" and "If final custom assets cannot all be produced, create a cohesive legally usable placeholder set and label it honestly in the asset manifest; do not pull unlicensed images from search results."

## Status: complete placeholder set, no sourced/downloaded assets anywhere

Every visual and audio asset in this build is **generated by code at runtime or build time** — nothing was downloaded, screenshotted, or copied from an existing game, artist, or stock library. This satisfies the brief's placeholder allowance but is explicitly **not final art/audio** — see "What a real art/audio pass would replace" below.

| Asset category | How it's produced | Where |
|---|---|---|
| Tiles (ground/wall) | Procedurally generated `Texture2D`s at region-load time: base region color + a deterministic per-pixel dither for texture, beveled highlight/shadow edges on wall tiles | `src/Lanternmere/Systems/TextureFactory.cs` |
| Player & NPC sprites | Procedurally generated silhouettes (circular head + tapered robe body) in per-NPC accent colors | `TextureFactory.CreateFigure` |
| Item/landmark icons | Procedurally generated glyph shapes (key, leaf, glass, book, flame, diamond, circle) via simple point-in-shape math, not sourced icon fonts | `TextureFactory.CreateIcon` |
| UI font | Rasterized at **build time** by the MonoGame content pipeline from "Segoe UI", a font installed on the build machine (standard MonoGame `.spritefont` workflow) | `src/Lanternmere/Content/Fonts/*.spritefont` |
| Music, ambience, SFX | Synthesized at startup from sine waves / filtered white noise (envelopes, tremolo LFOs, sweeps) — no samples, no recordings | `src/Lanternmere/Systems/AudioSynth.cs`, `AudioLibrary.cs` |

Nothing in `Content/` is a binary image or audio file checked into source control except the generated font `.xnb` build output (gitignored) and `Icon.ico`/`Icon.bmp` (the application window/taskbar icon, a simple generated bitmap, not sourced art).

## What a real art/audio pass would replace

- **Tile/sprite art**: hand-authored pixel art per the brief's art direction (base resolution, tile size, palette limits, animation frames) — the current geometric placeholder has no animation frames at all (no idle/walk cycles, no water/foliage motion, no lantern-lit vs. lantern-dark sprite states beyond color).
- **Font**: `UIFont.spritefont`/`UIFontLarge.spritefont` reference "Segoe UI" by name. This works for a local build on a machine that has it installed, but the shipped `.xnb` is a rasterized bitmap baked in at build time — a portable release build should point these at an embeddable, properly licensed font file instead, so packaged builds don't depend on what's installed on the machine that built them.
- **Audio**: real ambient recordings/foley and an actual composed score, mixed and mastered — the current synthesized tones and filtered noise are functional placeholders (they do loop cleanly and do crossfade) but are not "restrained musical themes" in any meaningful compositional sense.
- **Icons**: `ItemDefinition.IconPath` values (e.g. `"procedural:key"`) are documentation-only labels for where a real icon asset would eventually live; they are not read by any loader today since icons are drawn procedurally by shape, not by path.
